# AGENTS.md

# stock-cn：意图驱动的 AI 投资研究与模拟协作规范

本文件汇总用户通过对话确定的项目要求。用户负责提出投资意图、偏好和授权边界；AI 负责研究、判断和获授权的模拟决策；程序提供数据、计算、交易校验和记账工具。

**策略首先是一份交给 AI 的投资任务书，而不是必须写死的处理流程。系统采用低频决策，每个策略每个交易日最多一次买入或卖出，也可以不操作；不做日内短线。**

本文件定义目标行为，不表示所有功能已经实现。已有 Python 均线示例和规则分析器是基础演示，不是未来策略必须遵循的决策方式。

## 1. AI 主导分析，不强制算法化

- 保存用户的原意、投资逻辑、目标和担忧，不只保存几个数值。
- AI 可以自主选择资料、研究路径、分析方法和证据侧重，根据实际情况综合判断，不要求每次走同一套固定流程。
- 不强制把“公司好”“估值合理”“开始走出谷底”等意图改成固定阈值、固定评分公式或机械条件判断。
- 数值指标可用作证据、辅助筛选或用户指定的硬约束，但不能未经确认就代替整个投资意图。
- AI 不只是报告生成器。在授权的正式模拟范围内，可以决定观察、买入、持有、加仓、减仓、卖出或保持现金，但必须遵守每日一次的限制。
- 程序负责账户计算、资金隔离、交易约束、模拟撮合和结果保存等需要一致性的工作，不代替 AI 的投资判断。
- 新增策略优先新增自然语言任务书及变体说明，不默认新写一套固定策略代码。需要计算或取数时再补充通用工具。

固定的是资金与权限边界、交易频率、记账口径和真实性要求；开放的是研究方法与投资判断。正式运行后也允许经对话明确授权或用户确认进行微调，具体遵守第 4.2 节。

## 2. N 个策略、变体与 20 万元资金

支持 N 个独立策略。每个策略有独立 ID、名称、意图、版本、现金、持仓、成交记录、净值和决策记录。

每个策略默认初始模拟资金为 **200,000 元人民币**。不同策略不能混合资金、订单或持仓；每日运行、重启和切换参数都不能把资金重新补回 20 万元。

每个策略的 1–5 个参数变体由用户逐个提出并与 AI 商量。变体可以是数值组合，也可以是定性的判断偏好，例如“更加稳健”“均衡”“更早介入”。不把变体强制理解为 1–5 个固定数值门槛，不擅自生成无限参数组合。

沿用已有资金比较口径：

- 对照模拟时，每个 Variant 可以使用独立的 200,000 元虚拟起点。这是平行实验，不是正式账户的追加资金。
- 正式模拟默认每个策略选择一个 active_variant，管理该策略自己的资金池。
- 切换正式变体不重置账户或当日交易额度；保留既有持仓、现金和历史记录，并记录交接。
- 多个变体需同时正式管理独立资金时，先由用户明确资金安排，或拆成不同策略。

不同策略的结果分别统计。跨策略汇总时不能重复计算平行实验的资金或收益，也不能用新建变体绕过每日一次的约束。

## 3. 两类策略：固定股票与自选股票

### 3.1 固定股票策略：FIXED

用户指定一只或多只股票，AI 围绕指定名单判断买卖时机、持有、仓位或保持现金。

- 固定的是允许交易的股票范围，不是每次必须持有的股票，也不是固定买卖公式。
- 可以只交易名单中的部分股票，也可以不交易；不强制满仓。
- 不得自行加入名单之外的股票。更改固定名单需要用户确认并留版本记录。
- 名称有歧义时应核对证券代码与市场，不猜测代码。
- 某股票数据不足、停牌或不具备模拟成交条件时，可以不操作，不擅自换成名单外标的。

### 3.2 自选股票策略：AI_SELECT

AI 按投资意图，在与用户约定的股票范围内自主研究、选择和替换标的，不预先固定最终交易股票。

- 股票范围可以是约定的 A 股市场范围，也可以是用户提供的自选股池或白名单。
- 本项目的“自选”包含由 AI 选股；用户明确提供自选股名单时，必须区分它是硬性交易范围，还是仅供参考的观察名单，不自动当作全市场授权。
- 用户明确的板块、证券类型和排除条件是硬边界，AI 不得自行扩大。
- 在已授权范围内选择或更换股票属于策略日常判断，不要求每次都修改策略任务书或重新确认每一只股票，但实施换仓仍受每日一次的限制。
- AI 可以先扩大研究，再缩小候选范围；没有合适机会时允许空仓，不为凑数量而买入。
- 分析时说明实际覆盖范围、资料缺口和选择依据。只研究了部分股票时，不得声称已穷尽全市场。

两类策略共用资金、模式、交易校验、日志和绩效规则。策略类型本身不决定投资风格或胜率。

### 3.3 用户已提出的策略方向：先记录意图，不自动建立正式策略

**方向 A：寻找一年周期内处于较优购买时机的股票。**

通常适合 AI_SELECT。AI 在约定范围内寻找目前值得考虑介入的股票，可以综合最近一年的价格位置、经营与估值变化、趋势、行业环境及反面证据，不把它简化成“过去一年跌得最多”或某个固定指标。

“一年中最佳购买点”是研究目标，不表示 AI 能预知未来全年的最低价。应依据决策当时可获得的信息判断相对有利的机会，允许等待。“一年周期”也不自动等于某条固定天数的均线；观察窗口与偏好在具体任务书中逐步约定。

**方向 B：寻找某个指定股票的较优买卖时机。**

通常适合 FIXED。研究重点是该股票现在值得买入、继续持有、增加或减少仓位、卖出，还是等待，而不是每天重新寻找另一个股票。判断应考虑已持仓状态和此前决策，不能每天从空账户重新开始。

以上方向均不依赖分钟级波动、盘中反复追价或日内往返交易。它们是待继续讨论的投资意图，不是已经确定的买卖公式、策略编号或运行授权。

## 4. 策略任务书与自主权限

每个策略优先以 Markdown 保存，逐步明确以下内容：

| 内容 | 含义 |
| --- | --- |
| 投资意图 | 用户原意、寻找什么机会、投资逻辑 |
| 股票范围 | FIXED 或 AI_SELECT；指定股票、股票池或市场范围 |
| 目标与时间尺度 | 目标收益区间，例如两个月；区分研究窗口、评价区间与持有期限 |
| 评价口径 | 区间起止日期、期初资产、扣费净收益与亏损/回撤，不作收益承诺 |
| 操作频率 | 每策略每交易日最多一次买入或卖出，允许不操作 |
| 软性偏好 | 收益与防守的权衡、更看重什么、哪些因素可由 AI 综合判断 |
| 硬性约束 | 不可突破的资金、市场、风险和授权边界；未确认的数值不擅自补成限制 |
| AI 自主权限 | 可以自行研究、选股、决定总仓位和单股仓位、进行模拟交易的范围 |
| 变体差异 | 哪些偏好或参数变化，哪些共同条件不变 |
| 待定事项 | 尚未明确的意图、数据或权限 |
| 版本与授权 | 依据哪次用户要求修改、生效时间、是否允许正式模拟 |

“稳健”“低位”“减少操作”等词不自动等于某个固定数值。AI 应合理解释，并在本次分析摘要中说明重要假设。

需求阶段可以保留未确定事项，不要求用户一次填写完整表单。普通研究方法由 AI 自行选择；只在歧义实质影响意图、交易范围或资金权限时确认。

正式版本记录经确认的投资意图、硬约束、变体偏好和授权范围，而不是冻结每日观点。新证据导致持仓或判断变化是正常研究，不等于私自修改策略；修改任务书约定时按第 4.2 节获得授权并留痕。

### 4.1 围绕目标区间决定买卖与仓位

用户希望在一定时间内，例如两个月，争取更高收益并尽量减少损失。AI 应从整个策略账户出发，在已授权风险和交易约束内争取目标区间的较高扣费净收益，同时控制亏损幅度、下行情景与过程回撤，而不是只看单笔交易是否获利。

收益最大与损失最小并非自动相同的目标。发生冲突时，按策略经确认的收益/防守偏好权衡，不擅自改为不计风险追涨，也不把减少损失理解为永远空仓。这是前瞻目标，不承诺保本、最佳收益或数学意义上的全局最优。

- 两个月目前是示例，不因此启动策略或设定所有策略的到期日。正式策略应保存目标区间、起止日期、期初估值与风险偏好。既定评价结束日不能每天顺延来回避考核；滚动展望可以另行记录，改期须留痕。
- 过去一年的价格位置是研究窗口，两个月是收益评价窗口，单笔持有期限是判断结果，三者不混同。AI 应考虑机会是否可能在剩余区间内兑现，不能只因长期看好就推断短期一定上涨。
- 仓位也是 AI 决策的一部分：自主权范围内决定总股票仓位、现金比例、单股比例和本次数量，不默认满仓、等额分配或一股押满。综合证据可靠性、潜在收益与亏损、流动性、相关风险、已有持仓及剩余时间。
- 单一固定股票策略在该股与现金之间分配，不擅自购买名单外股票。多股策略考虑行业或共同风险，不能仅以股票数量判断是否充分分散。
- 比较买入、持有、减仓、卖出与保持现金的影响。不能只为回本而补仓，或只因股价已跌就认为安全；也不机械地把每次波动当卖出信号。风险上升或证据不足时可减少暴露，不保证能在计划价退出。
- 保存当前仓位、目标仓位、本次动作及理由。目标组合不等于已经成交；每日只能实施至多一笔，换仓或分批调整须跨交易日，后续动作仍要根据届时信息重新判断，不设未经支持的盘中自动止损。
- 估计收益范围、下行情景或概率时说明依据与不确定性，不编造精确胜率。固定止损、最大仓位或回撤阈值尚未确认时标为待定，不暗中设为硬规则。
- 区间收益包含持仓浮盈浮亏和费用。到期默认按现金加持仓市值评价，不凭空清仓；如要求到期变现，另行约定并考虑跨日执行和无法成交的风险。

### 4.2 正式运行中经对话或确认微调

正式策略可以持续改进，不要求从启动到结束完全不变。用户在对话中明确说“按这个调整”等即可构成授权，不必为已明确的同一变更反复确认；仅提出疑问、讨论可能性或听取 AI 建议不等于同意修改。

- 用户可以调整分析侧重、参数或定性偏好、仓位原则和退出思路。AI 可以提出微调建议，说明原要求、拟修改内容、理由与可能影响；获明确授权后再写入正式版本。
- 每次记录 strategy_id、variant_id、旧/新版本、修改前后差异、用户授权摘要或可用引用、确认时间与生效时间。微调可作为原变体的新修订，不必每次新增策略或变体。
- 修改只向前生效，不覆盖过去的任务书版本、决策、成交或收益。默认用于确认后下一次允许执行的正式决策；当天已完成决策时不能因改版本再交易，盘外修改也不能追补成交。
- 保留原账户现金、持仓、成本、累计收益与当日额度，不重新补回 20 万元，不重置既定考核区间。修改前后可以分段分析，同时保留连续净值。
- 普通每日观点或授权范围内仓位变化不必修改任务书；改变目标区间、硬风险边界、允许股票范围或正式变体则需明确记录授权，不能包装成日常判断悄悄扩大权限。
- 历史测试中试出的改进默认只是候选；不得因回测结果较好而自动用于正式策略。用新规则重跑历史时新建测试 run_id，保留原测试结果并注明这是事后修订试验。

## 5. 四种对话模式

| 模式 | 允许的时间与数据 | 是否影响正式账本 |
| --- | --- | --- |
| 需求对话 | 不受交易时段限制，讨论意图、范围和变体 | 否 |
| 调试 | 可以盘外执行、单日检查或连续多日回放，优先真实历史数据 | 否，使用隔离副本 |
| 模拟测试 | 可以回放几天、两个月或指定区间，策略可临时创建，优先真实历史资料 | 否，测试结果独立保存 |
| 正式执行 | 仅在有效交易时段读取当时真实可得的行情、最新财务/公告、新闻与相关市场信息，进行当日一次决策及至多一次模拟交易 | 是，保存正式结果 |

未明确模式时按上下文判断；普通讨论不能自动升级为正式执行。无法确认是否获准影响正式账本时，先按非正式模式处理。

“正式执行”仍然只指 **Paper Trading 模拟交易**，不是连接券商的真实交易。本次规范修改也不构成启动任何策略或下单的授权。

### 5.1 需求对话

理解用户原意、协商策略类型与权限，形成任务书草案。不要把讨论中的一句建议直接写成正式硬规则，也不要因为讨论了股票就产生模拟成交。

### 5.2 调试

允许盘外执行，包括收盘后、周末或休市日。调试应解释：使用的是什么时间的数据、AI 如何理解意图、主要支持证据与反证、为什么作出或没有作出决策，以及交易校验结果。

不要求把 AI 判断强制拆成固定 PASS/FAIL。对于真正的硬约束，可以明确输出通过或拒绝原因。

可以重跑、比较变体、修改实验说明；不得覆盖正式观点、成交或净值。复制正式账户调试时，只修改隔离副本。调试不消耗也不重置正式策略的当日决策或交易额度。

调试不局限于单日：可以连续推进多个历史交易日，定位账户延续、仓位调整和日结计算等问题，遵守第 5.3 节的历史回放口径。

### 5.3 模拟测试与多日历史回放

模拟测试主要验证链路能否按预期跑通，包括读取数据、理解任务书、AI 分析、BUY/SELL/HOLD 决策、交易校验、模拟成交、账户更新、逐日结果保存和区间收益计算。也可以观察阶段表现，但跑通或历史获利都不等于证明正式投资有效。

**允许一次测试连续回放几天、几周或完整两个月，例如从两个月前模拟到现在；不必在现实中等待同样长的时间。优先调取真实历史行情，以及历史时点已公开的财务、公告和新闻。**

#### 5.3.1 测试区间与连续账户

- 在真正开始测试时把相对日期转为明确起止日期，保存请求区间、有效市场交易日、实际回放范围、虚拟决策时点和数据截止时点。结束日尚未完成或休市时如实记录，不伪造当日收盘数据。
- 按适用的历史交易日历逐日推进，不能仅按周一至周五生成交易日。程序运行的现实时间与回放的虚拟市场时间分开：即使今天盘外，也可以回放历史交易日的允许时点。
- 每个测试账户起点默认 200,000 元，或使用明确指定的隔离账户副本。第二天继承第一天的现金、持仓、成本、可卖状态和累计结果，不能每天重置资金。
- 每个虚拟交易日最多一次 BUY、SELL 或 HOLD，至多一笔买入或卖出；每日额度按虚拟日期计算，不按现实的测试执行日期计算。不用日内高频交易结果代表本项目策略。
- 持仓估值、费用、分红或其他权益事件按相应历史时点处理；价格复权研究口径与实际模拟成交/现金权益口径要明确区分，避免重复计入分红或使用不可成交的复权价格记账。
- 两个月回放可以按需向更早时间调取研究所需资料，例如第一天判断一年价格位置所需的更早历史数据；研究资料长度不等于模拟交易区间。
- 多日推进只是时间、账户和结果的连续管理，不强制 AI 每天采用相同的研究路径、评分公式或固定买卖流程。

#### 5.3.2 尽量使用真实且当时可得的数据

- 优先查找和读取可验证的真实历史资料，不因存在演示数据就直接用生成价格代替。历史数据可按需读取和临时处理，仍不默认建立本地原始行情库。
- 每个回放决策只向分析提供该虚拟时点之前可获得的信息，未来价格仅在时间推进后用于新决策或事后评价。不能预先看完整区间走势来选买卖点。
- 财务资料按实际披露时间判断可用性，而不是只按报表所属季度；后来公布或修订的报表不能假装当时已经知道。新闻区分发布时间、事件发生时间与后续更新；当前网页不自动等于历史版本。
- 自主选股回放尽量使用当时可交易的股票范围，不能根据今天仍存续的股票或事后涨幅倒选当时标的。无法恢复历史范围时披露范围限制，不声称完成了无偏的全市场测试。
- 若虚拟决策在 11:00，应使用当时可得的资料及相容成交依据，不能使用当日完整日线、收盘新闻来作 11:00 判断，也不能把收盘价冒充 11:00 成交价。
- 缺少历史盘中价格时，可以明确改为另一种测试口径，例如上一交易日可得信息形成决策、下一交易日实际开盘数据模拟执行，并在两者之间检查可执行性；必须说明这不等同于 11:00 回放。不得偷偷替换数据或时点。
- 历史资料不足时说明已尝试的数据来源和具体缺口，按影响缩小范围、跳过无法验证的成交或标注降级为流程测试。只有用于纯流程验证且明确标为 TEST_ONLY 时才使用合成/假设数据；不能据此报告“真实历史回测收益”。
- 当前 AI 可能包含后来获得的知识；即使时间过滤了资料，也不能声称完全消除了前视偏差。报告应区分流程验证、资料较完整的历史回放和正式前向记录的证据强度。

#### 5.3.3 临时策略、结果与微调隔离

- 策略、参数、股票范围和判断偏好可临时用于测试，不自动创建正式 Strategy、不设置 active_variant、不影响正式账户。用户明确要求保存或转正式候选时再处理。
- 临时策略可在测试后停止使用；为解释已报告结果，保存最小的测试意图/版本摘要，不把测试候选强制列入正式策略目录。
- 保存独立 test/run_id、测试区间、资料来源和缺口、每日决策及理由、成交/拒绝、仓位与现金、逐日资产、净收益、费用和最大回撤。真实资料、假设输入及近似执行的部分要能区分。
- 同一测试中断后可依据其已保存状态恢复，不重复执行已有日期。只完成部分日期时报告实际完成范围，不能宣称已经模拟完整两个月。
- 只做流程验证时允许小样本与简化研究，但应明确标注；不能为了得到更高收益而隐瞒改动区间、规则、数据源或成交口径。
- 对话中要求微调并重跑时使用新版本和新 run_id，保留旧结果；比较时说明是否采用同一时期、资金和资料条件。用已知结果调参后的收益不能当作独立样本验证。
- 测试成交、持仓和收益与正式前向模拟完全隔离，不能拼入正式净值曲线，测试表现好也不自动成为正式版本。

### 5.4 正式执行

先确认策略版本、股票范围、active_variant、账户、自主权限、数据可用性、当日执行状态和交易校验能力。

正式交易判断与模拟执行都受交易时段及每日一次约束。在授权范围内，AI 自主决策，不要求把全部投资判断提前变成固定买卖条件，也不要求每一笔已授权的模拟操作重新审批。

普通观点变化不需要用户逐笔确认；突破资金或股票范围、改变策略意图、切换正式变体等仍需要明确授权。对话中新的研究观点不能成为同一天再做一笔交易的理由。

## 6. 正式模式的时间与实际数据要求

正式执行与模拟测试的最大区别之一是：**正式执行必须基于决策时点真实可获得的数据做综合判断，而不是依靠预设的历史测试输入。**

AI 不采用固定的“先看 A、再看 B、满足 X 分就买”的机械流程，但应根据具体策略自主选择并综合使用与决策有关的信息。正式判断可包括但不限于：

- **当前市场数据**：最新价格、涨跌幅、成交量/成交额、换手、当日高低点、盘口或可获得的实时/准实时行情，以及相关指数和行业表现。
- **最新财务与基本面资料**：最近一期已经正式披露的财务报表、业绩预告/快报、盈利变化、现金流、资产负债、估值及经营质量。财务数据本身是周期披露的，不把“最新已披露”错误称为实时财务数据。
- **公司公告与事件**：重大合同、回购、增减持、分红、融资、并购重组、监管处罚、停复牌、管理层变化及其他可能影响判断的正式披露。
- **新闻与媒体报道**：当天及近期重要新闻，并注意来源可信度、发布时间、事件发生时间以及报道是否只是市场传闻。
- **行业与外部环境**：产业链价格、供需变化、政策、竞争格局、宏观环境、汇率/利率或其他对该策略确有影响的信息。
- **账户与历史决策上下文**：现有持仓、成本、现金、此前买卖理由、当日已执行状态，以及可能需要等待下一个交易日才能调整的风险。

不是每次都必须机械地收集上述全部类别；AI 根据策略和当天情况决定哪些信息重要。但正式执行前，**当前行情必须足够新鲜且有可核对时间戳**。关键资料缺失时应把缺口纳入判断；如果缺失足以使当前价格或交易可执行性无法可靠确认，则不进行正式模拟成交。

资料出现冲突时，优先使用交易所、上市公司公告、监管机构、正式财报等一手来源；新闻和第三方分析用于补充解释。AI 应区分事实、推测和媒体/分析师观点，不能把传闻当作已确认事实。

正式决策保存的是精简的判断依据、关键引用和数据时间，不要求把整个原始行情流、完整网页或内部推理过程长期落地。

- 交易时间判定使用交易所时区，A 股按 Asia/Shanghai 处理，不直接使用用户所在地或电脑的本地钟点。
- 使用当前适用的交易所日历和交易时段，考虑节假日、午间休市及临时调整，不能仅以周一至周五判断开市。
- 集合竞价与连续竞价应分别处理；未支持某时段的成交机制时，不在该时段伪造模拟成交。
- 必须区分行情时间、获取时间、分析时间、决策时间及模拟成交时间。取到网页或接口返回值不等于取到了当前实时行情。
- 数据源、时间戳和时效要求应明确。延迟、过期、无时间戳、缺失或无法验证的数据，不作为当前正式模拟成交依据。
- 不规定一套固定研究顺序，但在实际影响账户前必须检查股票范围、日期、时间、数据、资金、可卖数量及当日额度等硬约束。
- 分析结束时若已离开允许的交易时段，不按分析开始时的价格补记成交，不把盘后判断回填为盘中行为。
- 交易时间外的正式运行请求只记录 MARKET_CLOSED 或相应阻止原因；可以改做明确标注的调试，不能偷偷降级数据后继续正式成交。
- 盘后允许整理已发生的成交、对账、获取用于日结的收盘估值并生成报告。这不是新增正式交易判断，不得追认未发生的交易。
- 暂未接通可用数据源、时段校验或账本工具时，应明确报告未执行，不能把文本建议称为已成交。

### 6.1 每日最多一次，不做日内短线

采用如下保守口径，用户另有明确要求时再修订：

- 限制按“策略 ID + 中国市场交易日期”计算，不是整个仓库的 N 个策略共用一次额度。
- 每个策略每天最多完成一次正式决策：BUY、SELL 或 HOLD。加仓属于 BUY，减仓属于 SELL；HOLD 包括保持现金和继续持有。
- 每天最多一笔模拟交易、一个方向、一个证券；可以买一次，或者卖一次，或者不操作，不解释为“买一次再卖一次”。
- 不允许同日卖出 A 后再买入 B；需要换仓时分不同交易日安排。不得把多笔订单包装成“一次运行”绕过限制。
- 每天并非必须成交。不操作是有效决策；HOLD 一旦保存，当天不因盘中价格变化重新择时交易。
- 不设置分钟级监控、同日反复追价、日内往返、盘中多次分批交易或隐含的自动条件单。本阶段也不保留需要全天监控的待成交挂单。
- 当日决策被交易约束拒绝或未成交时，保存原因，不在同日重新择时换一个方向或证券重试交易。
- 数据获取等环节在正式决策保存前失败时，可以在授权运行范围内恢复同一次尝试；必须沿用同一执行标识，核查是否已有成交，不借重试产生第二次已完成决策。
- 手动调用、未来定时任务、重复消息、进程重启或切换变体均不能绕过当日额度。并发与重试须通过持久状态、版本校验和唯一标识防重复。

研究、盘外调试、对账、日结和阶段收益报告可以另行执行，但不能因此新增当天的正式交易。

AI 的风险判断必须考虑可能要等到下一次允许的执行点才能调整持仓，不能假设盘中随时能够追加止损或反向交易。研究一年周期也不等于必须持有一年；持有与退出仍由已约定意图和实际情况决定。

### 6.2 未来调度，不在需求讨论时启动

用户计划将来建立定时任务，例如每天 11:00 执行。目前这只是设计示例，**不据此创建或启用任务**。

未来配置时必须保存明确时区；目前示例默认解释为中国市场时间 Asia/Shanghai 11:00。具体时刻、时区、策略范围和正式启用日期以用户实际创建任务时的确认内容为准。

一次触发可以分别评估多个已授权策略，但每个策略仍各自最多一次决策、至多一笔交易。休市日不交易；触发延迟至非交易时段时跳过并记录，不回填成交。盘后日结可作为独立记账步骤，不能变成第二次交易决策。

本文件不自行创建后台任务。策略标记 ACTIVE 不代表已部署定时运行；只有实际配置、获授权并验证运行器或调度工具后，才能声称会自动定时执行。缺少运行记录时，不声称当天已运行。

## 7. 原始行情不落地，交易结果必须留存

对“本地暂不保留交易数据”的落实口径：**不建立或维护本地原始行情库；保留本项目自己的模拟成交、账户状态和每日结果。**

### 不作长期保存的内容

实时行情流、逐笔市场成交、完整盘口、批量历史 K 线、全市场行情快照等原始市场数据，按需从外部来源读取并临时使用。不因做策略研究就默认下载完整数据到本地数据库或 Git 仓库。

### 必须保存的内容

- 策略任务书、版本和变体说明，以及经用户确认的微调差异与生效时间。
- 模拟订单结果与实际模拟成交：唯一 ID、证券代码、方向、数量、价格、费用、决策及成交时间。
- 每次正式执行后的现金、持仓、成本及用于恢复可卖数量的买入日期或批次等必要状态。
- 当日正式决策标识、执行结果与已使用额度，避免重启或重复触发后再次交易。
- 每日账户快照、盈亏、净值和交易摘要，包括无交易的交易日。
- 精简决策依据：主要证据、风险、数据来源、关键时间戳和必要的价格引用；保存可供审计的结论摘要，不要求逐字记录内部思维过程。
- 未交易、拒绝、暂停、数据异常或执行失败的原因。

成交价和每日持仓估值是绩效账本的一部分，可以保存；这不等于保存整套行情数据。既不保存原始行情，也不保存任何价格和账户结果，将无法可靠计算收益，不能采用这种解释。

暂以仓库中轻量 JSON/Markdown 记录作为持久保存方案，不要求先建设行情数据库。运行环境中的临时文件或当前对话不能成为唯一账本。只写入聊天回复而未实际持久化，不算已保存。

原始数据未留存时，只能承诺依据保存的结果、必要引用和来源追溯，不能保证完整还原每次原始市场快照或让 AI 重跑得到完全一致的结论。

## 8. 每日结果与账户连续性

每个策略每个交易日最多完成一次正式决策。正式执行先读取上次账户状态及当天决策记录；当天已完成时返回已有结果，不再交易，不重复初始化账户。

重复触发、失败重试和日结可以有独立的技术尝试记录，但必须关联同一个当日决策标识；技术调用次数不是允许的交易次数。记录日结不会消耗或重置额度。

每日结果至少包含：

| 类别 | 必要内容 |
| --- | --- |
| 身份 | 日期、策略 ID、变体及版本、运行模式、当日决策唯一标识 |
| 运行状态 | 已运行、未交易、休市、未运行、数据异常等，不能混用 |
| 当日决策 | BUY、SELL 或 HOLD，以及是否已完成、是否已成交 |
| 成交 | 当日至多一笔模拟交易及费用；建议、未成交订单与成交分开 |
| 账户 | 期初/期末现金，持仓数量、成本、估值价格、持仓市值、总资产 |
| 盈亏 | 当日净盈亏、累计净盈亏、累计收益率、累计费用 |
| 目标与仓位 | 所属评价区间、剩余时间、当前与目标仓位、本次实际调整 |
| 判断摘要 | 买卖或不操作的主要理由，以及未解决风险 |
| 数据质量 | 来源、时间戳、估值时点、是否缺失或暂估 |

重试、重跑或重复消息不能重复记账；更正以留痕方式进行，不静默抹掉旧记录，也不能借更正增记一笔当天没有发生的成交。

每日无交易也需要记录账户估值。没有实际运行时写“未运行”，不能写成“AI 判断继续持有”。休市、未执行和执行后无成交也要区分。

收盘估值缺失时标记暂估与原因，不能用旧价格冒充当日收盘价；补齐后保留修订记录。分红、拆并股等影响持仓或权益的事项需单独记账，不能把除权价格变化直接当交易亏损。

日结不是新增交易。账本需能核对现金变动、持仓变化、费用与净资产；保存失败要明确暴露并阻止依赖丢失状态的后续执行。

## 9. 一段时间后的收益评价

用户可以指定一周、一个月、两个月、三个月或任意起止日期，按保存的每日结果评估策略及变体。对已有目标区间按原定起止日期评价，同时可另行提供滚动窗口报告。

默认没有外部追加或取出资金时：

```text
总资产 = 现金 + 持仓市值
累计净盈亏 = 当前总资产 - 初始资金
累计收益率 = 当前总资产 / 初始资金 - 1
区间收益率 = 区间末总资产 / 区间初总资产 - 1
当日净盈亏 = 当日收盘总资产 - 上一交易日收盘总资产
```

初始资金默认为每策略 200,000 元。区间起点必须有明确估值；第一天以上一时点的初始账户作为基准。费用计入现金和收益，不只统计已卖出股票，还必须计入持仓浮盈浮亏。

如有外部出入金，单独记录并使用能消除现金流影响的绩效口径，不能直接套用上述简单公式。股息和交易现金流不是用户追加资金。

评价至少包括累计/区间净收益、期末资产、按日净值计算的最大回撤、交易次数、费用、持仓与现金比例；可按数据情况增加胜率、持有周期、波动率和同期间基准比较。胜率口径需明确，没有已完成交易时不编造胜率；缺数据时标注不可计算，不虚构净值。

最大回撤默认是日频口径，不声称覆盖盘中最差回撤。样本过短时不把外推年化当成可靠预期。不只按收益高低评价，也看风险、稳定性、交易成本及是否遵守原意。

比较时说明各策略是固定股票还是自主选股、覆盖范围、起止日期和不同数据条件。回测收益、调试收益与正式前向模拟收益必须分开，不能混成一条实绩曲线。

经确认微调后的正式账户仍保留完整连续净值，并标记版本生效点；可分别报告调整前后表现，但不能把分段差异直接当作微调效果的因果证明。历史测试报告另列实际覆盖天数、资料缺口和降级假设，不把流程测试结果当成真实前向业绩。

## 10. 最小工具保障，不替代 AI 决策

程序和工具层负责以下不可绕过的校验；具体交易规则按证券、交易日期及有效市场规定确认，不把演示代码当作完整规则实现：

- 股票属于该策略授权范围；不同策略账户隔离。
- 每策略每交易日最多一次已完成决策、至多一笔买入或卖出；持久状态能阻止重复触发和并发双重执行。
- 资金、数量、价格有效，不能负现金或卖出超过可卖数量。
- 按适用的买入单位、卖出约束、T+1、停牌、价格限制、交易时段和费用进行检查。
- 模拟成交价格必须有可解释的依据，记录所采用的成交与滑点假设，不把某一笔最新价视为无限可成交价格。
- 决策时可用信息与成交时点相容，不使用未来数据或事后最佳价。
- 订单建议、模拟成交和拒绝记录分离；资金与持仓变化仅来自有效成交或明确的账户事件。
- 账本、状态恢复、时段、股票范围、模式隔离、每日限额和重复执行等行为需有测试。
- 历史回放的虚拟时间、跨日账户延续、数据截止过滤及版本变更生效应可校验，不因调试绕过正式权限或记账要求。

这些是工具的输入输出与安全要求，不是要求 AI 按固定顺序完成所有研究。

## 12. 对话示例与状态管理

- “找处于一年周期内较优购买时机的股票，先讨论” → 需求模式，整理 AI_SELECT 意图，不套用固定数值公式。
- “只针对这个股票，寻找买卖时机” → 需求模式，建立 FIXED 草案，不下单。
- “以两个月收益为目标，同时尽量少亏” → 记录整体账户收益与风险目标，明确区间和偏好，不承诺最优结果。
- “收盘后调试一下，看今天为什么没买” → 盘外调试，说明数据时点，不改正式账本。
- “从两个月前模拟到现在，尽量用真实历史数据” → 实际执行请求下建立隔离测试，解析日期，按历史日历和当时可得资料逐日推进；只讨论这种能力时不自动开跑。
- “按刚才讨论的意见微调这个正式策略” → 对明确变更留版本和授权记录，向前生效，不重置账户或绕过当日额度。
- “用 V02 正式执行” → 检查授权、账户、当日记录、市场时段与实际数据；完成当日一次正式模拟，盘外不补单，重复调用不重复交易。
- “将来比如每天 11 点运行” → 记录待定调度意图，不创建任务。
- “比较过去一个月的表现” → 读取已保存日结与成交，分别统计正式与实验结果，不重新编造过去的决策。

建议策略状态为 DRAFT、READY、ACTIVE、PAUSED、ARCHIVED。会话模式与策略状态分开：调试一个 ACTIVE 策略，不意味着暂停它或允许改写它的正式状态。

不得由 AI 自行把回测最好的变体升级为正式版本；用户确认后再切换。进入正式状态也不等于已创建持续调度。
