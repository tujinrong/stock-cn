# 模拟模式与正式 Paper Trading 的同构设计

目标：历史模拟通过后，不重写投资逻辑和交易记账，只替换“时间与数据适配器”，平顺切换到正式 Paper Trading。

## 共同核心

SIMULATION 与 FORMAL 共用：

1. 每个变体自己的完整提示词与账户；
2. 同一个 AI decision JSON 契约；
3. 每交易日最多一个完成决策、至多一笔订单；
4. 同一套股票范围、科创板排除、数量与T+1约束；
5. 同一套佣金、印花税、过户费计算入口；
6. 同一个 `paper_core.execute_single_order` 资金/持仓更新函数；
7. 同样的 HOLD、REJECTED、FILLED 和资料不足语义；
8. 事件→持仓→日结的文件式记账思想；
9. 相同提示词版本哈希与账户revision校验。

因此不得出现“测试时一种会计逻辑、正式时另一种买卖逻辑”。

## 允许不同的地方

| 项目 | 历史模拟 | 正式Paper Trading |
| --- | --- | --- |
| 数据截止 | 历史虚拟时点 | 当前真实时点 |
| 数据 | 当时已公开历史资料 | 当前最新可核实行情/财务/公告/新闻 |
| 成交价 | 当前日线MVP：前收判断、次日开盘代理 | 已验证当前报价，正式落地前仍需实时源验收 |
| 输出目录 | variant/simulations/<test_id>/ | variant正式账户/当日目录（尚未启用写入） |
| 账户 | 隔离测试账户 | 独立正式Paper账户 |
| 结果用途 | 验证、比较、改进 | 前向Paper Trading实绩 |

测试盈亏、测试持股和test_id **绝不复制到正式账户**。

## 提示词切换

每个变体有两个指针：

- `simulation_prompt.json`：新模拟测试使用的已验证候选版本；
- `formal_prompt.json`：正式模式批准使用的版本。

自动改进最多10轮，只能自动改变 simulation 候选。要把某个测试版本用于正式模式，必须经过用户明确确认，然后只把**同一个完整提示词版本/哈希**提升为 formal_prompt；这一步本身仍不启用正式执行。

`cutover_readiness()` 会检查：

- 模拟提示词与正式提示词是否为同一哈希；
- 全局正式开关；
- 变体 READY/ACTIVE 与 enabled；
- 正式账户是否已初始化；
- 正式账户 execution_enabled。

所有条件通过才是“可正式运行”，不能因为测试成功自动切换。

## 实时快照要求

FORMAL 输入使用 `LIVE_SNAPSHOT`：

- market_date 与 as_of 一致；
- as_of 必须处于当前支持的连续竞价时段；
- 行情有 source 和 quote_time；
- 默认报价不能旧于5分钟；
- 涨跌停元数据必须齐全；
- 新闻/公告发布时间不得晚于 as_of；
- 仍然排除科创板；
- 数据不足就阻止正式成交，不降级成猜测价格。

目前 `FormalPaperSession.execute_preview()` 只在内存中用共同执行核验证结果，不持久修改正式账户。这是为了先证明模式同构；正式写账仍需在用户确认正式启用、实时数据源验收后接上。

## 验收标准

CI 必须证明：

- 相同账户、订单和成交价，在 SIMULATION / FORMAL 下产生相同现金和股数；
- 未来新闻、未来报价、过期报价、午休/盘外快照被拒绝；
- 模拟提示词候选不能未经授权升级为正式提示词；
- 正式预览不修改 holdings.json；
- 既有历史模拟、T+1、每日一次、并发隔离测试全部继续通过。

这样正式上线时变的是“数据和授权”，不是投资策略与交易核心。
