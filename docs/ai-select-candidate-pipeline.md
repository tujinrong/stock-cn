# AI_SELECT 候选池与深查契约

适用：D、E、F等 `AI_SELECT` 系列。目标是在不对数千只股票逐只做昂贵深度研究的前提下，让AI仍能从较宽市场范围发现机会。

## 两阶段

### 阶段1：宽市场轻筛

输入为当前或明确历史时点可用的证券集合和轻量横截面数据。只做：

- 排除项目不支持的证券范围；
- 检查代码、名称、价格/成交等基础字段；
- 按策略目的形成有限研究种子，例如年度低位回升或异常下跌；
- 将候选数量限制在可控预算内，首版一般不超过30～60只。

**轻筛不是推荐模型。** 候选排序不得直接成为BUY/SELL或“Top股票”；只能决定下一阶段把计算资源花在哪些股票上。

### 阶段2：有限候选深查

仅对候选池获取较长历史K线并生成与时光穿越相同的价量摘要；再把：

- 当前账户；
- `AUTHORIZED_UNIVERSE`；
- 候选的K线、区间位置、波动、异常断点；
- 实际已核实的财务/公告/新闻（若有）；
- 数据缺口和来源；

一起注入**该变体自己的完整提示词**。最终股票选择、仓位和BUY/SELL/HOLD仍由AI完成。

## D02与F01的差别

- D02：从较宽股票集合中寻找“质量没有明显受损 + 相对低位 + 已有回升确认”的机会。第一阶段不允许仅按跌幅排序。
- F01：可以重点纳入近期明显下跌股票，但第二阶段必须排除除权/送转/数据口径断点，并判断下跌是否可能来自真实基本面恶化；不能“跌得多就买”。

## 计算量边界

- 宽市场列表可以一次轻量读取；
- 单次深查候选必须有限；
- 同一时点、同一股票的历史价量摘要可被多个AI_SELECT变体只读复用；
- AI提示词和账户仍按变体独立；
- 数据预算不足时缩小深查范围并明确披露，不能声称已完整研究全A股。

## 历史模拟特别限制

今天的上市股票名单不能直接冒充过去日期的完整证券集合，否则存在幸存者偏差。历史AI_SELECT测试若没有历史证券主数据，只能标记为：

`SURVIVORSHIP_LIMITED_HISTORICAL_CANDIDATE_SET`

并明确说明候选范围，而不能写“当时全A股扫描”。

## 正式模式

正式Paper Trading可以使用当日当前证券集合做宽市场轻筛，但正式成交仍需独立通过：

- 当前交易日/时段；
- 报价新鲜度；
- 停牌和涨跌停；
- 当前股票范围；
- 账户、资金、T+1和每日一次规则。

研究候选池成功不等于正式报价已验收，也不自动授权交易。
