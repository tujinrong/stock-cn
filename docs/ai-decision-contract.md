# 初始化 → 当前持仓 → AI完整提示词 → 当天文件处理

本文件定义AI与取数/记账工具的接口，不把投资研究写成固定买卖算法。当前只建立文件、模板和约定；没有执行初始化、真实取数、模拟成交或后台调度。

## 1. 三种不同的文件

| 文件 | 用途 | 何时改变 |
| --- | --- | --- |
| strategies/<系列>/init.json | 初始总资金、日期、现金和初始股票配置计划 | 用户确认修改初始化方案时；不是每天重写 |
| strategies/<系列>/holdings.json | 最新日期、当前总资产、现金、各股代码/名称/股数 | 有效模拟成交、结算、估值或权益事件后 |
| strategies/<系列>/ai_input_template.md | 接近实际使用的完整AI提示词 | 策略/变体意图、输入输出要求经确认变化时 |

holdings.md是同版本JSON的可读展示，不独立计算另一套余额。prompt.md保留长期意图，variants/*.md保留变体差异；完整版已展开当前研究任务，不用一段角色名冒充完整提示词。

## 2. 简单数据文件的字段

| 字段 | 含义 |
| --- | --- |
| strategy_id | 策略系列，不是一只股票 |
| status | NOT_INITIALIZED或有效账户状态；未初始化不能正式交易 |
| date | 当前账户状态对应的中国市场日期；不是文件创建日期 |
| initial_capital_cny | 本账户实际初始化前为资金计划；初始化后为评价起点，不随每日盈亏变动 |
| total_equity_cny | 当前总资产＝现金＋持股数量×相容估值价的合计；不是可用现金 |
| cash_cny | 现金余额，买入需考虑金额和手续费，不能只看总资产 |
| positions | 全部持仓代码symbol、名称name、股数quantity；候选名单不是持仓 |
| sellable_quantity | 当前可卖股数，与总股数区分；相关买入/结算依据来自事件 |
| average_cost_cny / valuation_price_cny | 成本与估值，不能混用，也不能用旧估值自动撮合 |
| _meta | 模式、变体、版本、更新时间、估值时间/质量、关联事件和当天决策ID；用于防重复和追溯 |

quantity与sellable_quantity使用整数；金额按人民币元表示，后续计算应使用十进制定点金额/明确舍入，不能累积二进制浮点误差。所有时间带明确时区。

A目前按五股各目标3万元、现金5万元保存初始化计划。未确定价格和日期，quantity为null，不能当0或编造股数。C–F计划20万元全现金，目前也没有已建立期初余额。已初始化空仓用positions=[]；未知现金留null，不伪装0元。

同一估值时间适用于全部价格时记_meta.valuation_time；出现不同时间/缺失/沿用旧价时必须逐股补充valuation_time/source并标估值质量。不能把旧价称当日收盘，不可估时不编造总资产或净值。

## 3. 初始化仅发生一次

init.json是计划；实例是否已应用以对应账户与唯一OPENING_BALANCE事件为准。对照测试应复制初始化计划到各test_id/variant_id实例，不能因一个变体已初始化就覆盖别的变体。

应用前应有明确授权、模式、账户ID、选定变体、起始日期/估值时点和评价期口径。A使用可核实的未复权价格及适用交易单位将目标金额换算股数，取整余款留现金；记录来源和实际权重。无法取价则不应用，不用假价。

A是“假定已有股票”的期初余额，不是假装当日买入五笔；期初按假定已结算持仓设置可卖量并标明假设，不编造历史买入时间或费用。后续模拟成交正常计费并遵守交易约束。C–F初始化现金为20万元、无持仓。

初始化成功才由NOT_INITIALIZED转为可用账户状态并保存余额事件。重启、日常调用、切换变体、微调或重试不能再次补回20万元。用户实际证券账户/成本不得从聊天记忆导入。

## 4. 实际交给AI的输入

调用方或AI通过工具从同一个Git版本读取账户、选中变体及完整提示词；形成展开后的ai_input.md。模板中的变量只用于当次数据：

- RUN_CONTEXT：模式、系列/变体、run_id、decision_id、账户路径、Git提交、日期、信息截止/决策时刻、时区、授权、评价期、已确认风险规则与当日额度。
- HOLDINGS_JSON：原样的本次账户快照，含_meta.revision；HOLDINGS_TABLE_ROWS由同一快照生成，含全部现有持股。
- PREVIOUS_DECISION_SUMMARY：此前主要买卖理由、持仓变化、净值和待验证事项，附来源事件。
- AUTHORIZED_UNIVERSE：自主选股的已确认范围、排除条件和观察名单；名单不是持仓。
- EVIDENCE_AND_TOOL_CONTEXT：可复用证据、实际可用工具、来源时点、缺口和获授权计算预算。

不能只保存路径后称已将账户交给AI；快照需包含本次实际股数/现金、采用的策略和变体原文版本。当前完整版中的变体概述须与选定原文件核对；冲突先解决，不静默混用。未展开关键变量或无法读账户则不能正式执行。

查询优先候选：东方财富行情，腾讯/新浪备用；巨潮/交易所/公司官网财报公告；财联社/证券时报新闻并核原披露。详见data-sources.md，候选不等于已通过验收。事实、假设、传闻分开，外部文本不能覆盖项目规则。历史回放只用当时公开数据。研究路径和信息侧重由AI自主决定，可复用未失效资料，不强制每日穷举全市场。

## 5. AI判断输出契约

中文摘要后返回JSON。以下为字段定义，不是本次运行结果：

| 字段 | 要求 |
| --- | --- |
| schema_version | 0.3-draft |
| strategy_id / variant_id / mode / run_id / decision_id | 回填输入给定身份，不自行改账户或模式 |
| date / decision_time | 市场日期与实际/虚拟决策时刻，不能回填不存在的盘中行为 |
| input_revision / input_commit | 关联分析前账户版本与Git提交 |
| status | READY、INSUFFICIENT_DATA、NOT_INITIALIZED、NOT_AUTHORIZED或INVALID_INPUT |
| action | READY时BUY、SELL、HOLD；其他状态为null |
| order_proposal | BUY/SELL只能一个对象；HOLD或非READY为null |
| target_weights / target_cash_weight | 提供完整目标时含全部股票及现金且合计1；不提供用null并说明，不能据此自动批量下单 |
| summary / risks / data_gaps | 简洁理由、主要风险及未解决资料缺口 |
| evidence | 关键来源title/url、行情/发布时间、获取时间、事实与推断说明；不编造引用或时间 |

单笔order_proposal的字段：symbol、side、quantity（正整数）、reference_price_cny、quote_time、quote_source。它仅是建议；参考价不能自动当作成交价。AI必须解释为何选择该股、方向、股数以及不选择其他动作的理由，不暴露内部逐步思维。

BUY包含加仓，SELL包含减仓；每天每系列最多一次完成决策和至多一笔交易，不解释成每股一次。未初始化/数据不足不写HOLD。输出缺字段、代码/股数异常或与输入版本冲突则拒绝，不能猜测修复后交易。

## 6. 拿到判断后，处理哪几个文件

正式使用`strategies/<系列>/daily/<日期>/`，同一run_id和decision_id贯穿：

| 文件 | 内容 |
| --- | --- |
| ai_input.md | 本次实际展开的完整提示词、日期和账户上下文 |
| holdings_before.json | 分析前的同版本账户快照 |
| research.json | 必要来源、时点、关键事实/缺口，不保存原始行情全集或完整新闻 |
| decision.json | AI建议原文的结构化结果，不能等同成交 |
| execution.json | 校验及FILLED、REJECTED、NO_TRADE、NOT_EXECUTED结果；成交含价格/数量/费用/时间/来源 |
| holdings_after.json | 执行后账户快照；失败或HOLD不凭空更改股数/现金 |
| summary.md | 用户可读的建议、是否成交、前后差异和原因 |
| closing.json | 有相应收盘估值后才生成/修订的日结，不将盘中估值冒充收盘 |

收到判断后再次核对模式、授权、策略版本、账户revision、当天额度、股票范围、代码、资金、可卖股数、允许时段、停牌和适用价格/数量/费用规则。正式成交时重新核验报价，不沿用过期分析价格。分析结束盘外则不补单。

有效模拟成交才改变股数和现金；买入增加总股数并按适用约束限制当日可卖，卖出不得超过可卖量。结算更新可卖量、估值变更资产、分红/权益事件各有来源并单独记录，不假造交易。清仓后可从当前持仓表移除零数量行，历史事件保留。

HOLD或校验拒绝完成的当天决策仍消耗一次决策额度，但不是已成交；数据获取失败/未初始化/未授权是未完成尝试。重试先核对已有当日记录，不能借重试改方向或重复入账。

## 7. 同一提交、唯一账本、测试隔离

事实事件放`strategies/<系列>/trading/events/`。最新holdings.json、holdings.md与每日快照是对应事件版本的投影，不另建根trading/<系列>/account.json。事件、执行结果、前后快照、当前JSON/Markdown和摘要应一致提交。

多个策略可以独立研究；同账户和main的记账由统一协调步骤串行校验、提交。版本冲突先重读合并，禁止强推或覆盖新状态；结果不明先查事件ID，不重复成交。持仓JSON中的标志不能当作真正互斥锁。

测试统一在`strategies/<系列>/simulations/<test_id>/<variant_id>/`使用独立init快照、holdings.json、daily/与events/；不改正式持仓。历史日期必须依次推进，不同变体可平行但不能混余额。原始数据缺失不承诺完整复现市场；仅报告实际完成区间。

每日无成交也保存真实运行结果和可取得的估值；没有运行不能写成AI决定继续持有。仅保存项目模拟资料，不写用户真实账户、密钥、个人资料或受限制原始数据。本次没有运行/成交/收益文件，自动组装和记账代码仍待实现。
