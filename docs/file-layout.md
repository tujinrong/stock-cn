# 纯 GitHub 文件结构与异步运行设计

状态：设计约定，未实现运行器。用户已要求不用数据库，策略确认后再开始编程。Markdown 为可读主入口，JSON 为结构化记录，CSV 为可重建的报表。正式模拟仍非真实券商交易。

## 2. 编号、资金与草案确认

A=招商银行；B=比亚迪；C=优质股年度低位；D=业绩改善；E=招商银行/比亚迪/现金分配。每个字母是一个策略/资金池，编号如 A01 是变体。A01与A02可平行测试，但不能把两个正式任务同时写入策略A的20万元账户。

index.json 保存策略 ID、类型、草案范围、initial_cash_cny、variants、active_variant、status、enabled。初始资金字段是待启用配置，不是已开账户或已发生出资。

当前全部 DRAFT，未确认目标起止日期、硬仓位边界或正式变体。确认后再按明确授权更新为 READY/ACTIVE并留下 changes.md；启用元数据本身不能取代账户、数据与调度工具的实际验收。

## 3. 用户能看到的提示词

一次投资任务的项目提示词由以下可见内容组合：AGENTS.md 的适用边界、strategies/common.md、策略 prompt.md、选中变体文件，以及用户已经确认的具体区间、模式和任务补充。

运行前保存这些文件的 Git 提交/校验值，运行时将实际组合后的投资指令保存在对应 prompts/<run_id>.md 或模拟 prompt.md。附加项目指令也需可见，不能悄悄换成固定算法。账户和证据以引用及精简输入记录关联；只承诺公开项目提示词，不包含服务内部系统指令或私密思维过程。

仅执行结果摘要不够，用户应能回答“这次到底用了哪份提示词”。每次修改向前生效；旧快照、成交与净值保留，不因微调覆盖。

## 4. 事实、账户与每日结果的字段约定

以下为后续实现的字段要求，不是已生成的真实样例数据。

| 文件 | 必需信息 |
| --- | --- |
| event.json | schema_version、event_id、run_id、模式、strategy_id、variant_id、版本、账户序号、前一事件ID/校验值、市场日期、发生/数据/决策/模拟成交时间；决策与订单结果、有效fill、费用、事件后账户、证据引用和提交状态 |
| account.json | account_id、模式、策略、人民币币种、初始资金、当前现金、持仓、买入批次/可卖状态、累计费用、最近事件与序号、当日完成决策标识、prompt版本、更新时间 |
| result.json | BUY/SELL/HOLD或DATA_UNAVAILABLE等运行结果、当前/目标仓位、订单建议和实际fill分开、未成交/拒绝原因、行情时间和来源、prompt路径/校验值、关联event_id |
| closing.json | 期初/期末现金与权益、持仓成本数量、估值价格及其时间、估值是否暂估、当日/累计净盈亏、收益、费用、股息与其他权益事件引用 |
| summary.md | 为什么买卖/不操作、最重要证据与反证、主要风险、仓位变化、资料缺口；不写内部逐步思考 |
| manifest.json | 本次模式、选择策略/变体、资金口径、评价/模拟区间、信息截止时间、时区、取数来源、prompt版本、执行假设、实际完成范围 |

日常的“AI判断HOLD”与“数据失败未能判断”“未运行”不同。HOLD记作已完成当日决策，数据失败记录为失败尝试；重试仍需查询同一日是否已经完成，不能重复成交。

金额用确定的人民币小数口径，证券代码保留前导零与市场后缀，数量用整数，时间用明确偏移量和市场时区。费用与复权/股息口径在run中固定并记录。字段精确定义在策略确认后的通用工具实现中验收，不在本次伪造运行记录。

## 5. 无数据库的可靠记账

已提交 events 是唯一事实源；account、日结与CSV能根据事件重建并核对。行情估值和股息等也是带来源的账户事件，不能被当作用户追加现金。修订新增纠正事件并引用原事件，不删除不利结果。

一次正式决策需把事件、账户投影、当日结果与prompt引用作为同一完整提交保存。只有已提交且可校验的结果才宣称已记账。进程中断、网络失败或提交结果不明时，先查唯一ID是否已经存在，不能重试产生第二笔。

幂等标识至少区分正式/测试、账户、市场日期与本次决策。正式每日额度属于策略/账户而非变体。历史模拟使用虚拟日期及test_id隔离。账户序号只前进，旧任务不能覆写新状态。

一个JSON文件写lock=true并不能提供可靠互斥。拟采用唯一提交协调者串行写账，在最新main上校验前置版本、合并独立策略结果、创建多文件提交并非强制更新。若main已被其他人/任务推进，重新读取，按事件ID去重再提交；不强推、不用后写者覆盖前写者。

## 6. 后台异步的目标结构

一次已授权批次可并发研究多个策略；每个策略是独立任务，有可见状态、错误、输入版本、产出路径和运行时间。一个失败不拖住其他独立任务。并发数、超时及服务用量按实际环境验收后设定，不保证无限并发或固定完成时刻。

拟议状态：QUEUED、RUNNING、COMPLETED、FAILED、SKIPPED、CANCELLED。COMPLETED仅表示本任务有可验证结果，不等于发生了买卖；成交以events为准。状态恢复以已提交事件和账户为准，不只依靠容易过期的status.json。

跨策略/隔离变体可并行，同一账户的决策和记账串行。历史回放必须逐日推进：某策略第二天依赖第一天账户，不能把两个月所有日期独立并行后拼接。允许不同策略各自按顺序同时推进。

可共享同一信息截止时点的只读公共资料，节约重复访问；保留来源/时效，不能让较晚任务或未来资料污染历史回放。正式成交前仍需刷新并核验报价和交易时段；研究耗时不同意味着实际成交时点可能不同，应在比较报告披露，不虚构统一11:00成交。

分析结果归集到提交协调者，只有仍符合授权、账户版本、当日额度和时效的结果才能形成正式账本。汇总完成部分和失败部分，不等待失败者无限挂起，也不擅自补发盘后交易。

本次只建立文档。没有新建投资工作流、云服务、API调用、任务或付费订阅。后台持续运行需要后续实际配置、授权并验证执行器，不能由文件存在推断已启动。

## 7. 数据留存与安全

不使用任何数据库，不把原始实时流、全市场快照、批量K线、完整新闻全文或大包行情长期放进Git。可按需临时下载处理，当前回放结束清理；保存精简来源引用、时间、关键判断输入、成交和估值即可。

真实历史资料不可得时记录具体缺口，不把生成数据称真实。仅纯流程测试允许明确标注TEST_ONLY的假设数据。原始快照不全保留时不保证完全还原市场或AI相同输出。

正式和测试文件不要进入临时清理或忽略规则。任务重试日志保留可解释最小记录；CSV报告按日期/区间生成，不把不断增长的大表当主账本。后续规模较大再讨论分年归档，未授权不删除历史结果。

仓库可能公开，不写用户实际证券账户、真实仓位与成本、私人联系方式、密钥或受限制数据。模拟策略中的公开证券名单不表示披露用户真实投资组合。
